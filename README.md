📥 ขั้นที่ 5 — เปิด Pull Request
 
เมื่อ Push เสร็จ → เปิดลิงก์ที่แสดงในเทอร์มินัล หรือไปที่หน้า GitHub:
 
ช่อง ควรเขียนอะไร 
Title ประเภท: หัวข้อ (เช่น  docs: เพิ่มคู่มือร่วมพัฒนา ) 
Description สรุปสั้นๆ · สิ่งที่เปลี่ยน · ภาพหน้าจอ/ตัวอย่าง (ถ้ามี) 
Reviewers เชิญผู้ตรวจสอบ 
Assignees มอบหมายให้ตัวเอง/ทีม 
Labels  documentation  /  enhancement  /  bug  /  ready-for-review  
 
✅ เช็คลิสต์ก่อนเปิด PR
 
ทดสอบผ่าน:  npm test 
รูปแบบถูกต้อง:  npm run lint 
ไม่มีข้อมูลลับ/รหัสผ่าน
เอกสารอัปเดตแล้ว
อ้างอิง Issue ที่เกี่ยวข้อง
 
 
 
🔍 ขั้นที่ 6 — ตรวจสอบ & Merge
 
ในฐานะผู้ตรวจสอบ
 
- อ่านคำอธิบาย → เข้าใจวัตถุประสงค์
- ตรวจสอบโค้ด → ความปลอดภัย · ประสิทธิภาพ · ความชัดเจน
- รันทดสอบ → ตรวจสอบว่าทำงานจริง
- แสดงความคิดเห็นอย่างสร้างสรรค์ 🤝
 
เมื่อได้รับการอนุมัติ
 
- เลือกประเภท Merge:
- Squash and Merge ✅ แนะนำ — รวมเป็น 1 commit สะอาด
- Create Merge Commit — เก็บประวัติทุกบรรทัด
- Rebase — จัดเรียงใหม่ตามต้องการ
- ลบ Branch หลัง Merge เสร็จ ✅

ประเภทที่ใช้เสมอ
 
ประเภท ใช้เมื่อ 
 feat  เพิ่มฟีเจอร์ใหม่ 
 fix  แก้ไขบั๊ก 
 docs  เอกสารทุกชนิด 
 refactor  ปรับโครงสร้าง ไม่เปลี่ยนผลลัพธ์ 
 test  เพิ่ม/แก้การทดสอบ 
 chore  อัปเดต dependencies, งานทั่วไป 
 
 
 
❓ คำถามที่พบบ่อย
 
ถาม: ชนกันทำไหม?
 
 
 
ถาม: PR ใหญ่เกินไปทำไหม?
แบ่งเป็นชุดเล็กๆ:
 
- ชุดที่ 1: เพิ่มโครงสร้างเอกสาร
- ชุดที่ 2: เขียนเนื้อหา
- ชุดที่ 3: ปรับรูปแบบและตัวอย่าง
 
ถาม: ลืมสร้าง branch แก้ไขที่ main ไปแล้ว?
 
 
 
ถาม: ต้องการทำงานร่วมกันบน branch เดียวกัน?
 
- พูดคุยตกลงกันว่าใครทำส่วนไหน
- Push บ่อยๆ เพื่อให้เห็นความคืบหน้า
- Pull ก่อนแก้ไขเสมอ
 
 
 
💬 ทำงานร่วมกันอย่างเคารพ · ช่วยเหลือ · สร้างสรรค์ นี่คือหลักสำคัญที่สุด ❤️
